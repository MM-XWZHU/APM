
# 🧠 PI 核心概念速查（极简版）
## 1️⃣ 三层结构（先记这个）

```
Tag（数据层） → Attribute（语义层） → Analysis/Expression（计算层）
```


```
PI System 分三层：

① 数据层（PI Data Archive）
   → Tag（PI Point）

② 语义层（PI AF）
   → Element（资产）
   → Attribute（属性）

③ 分析层（PI Analytics）
   → Expression（计算）
   → Event Frame（事件）

④ 应用层
   → KPI / 状态 / 指标（其实是 Attribute 的语义）
```

---

# 2️⃣ Tag vs Attribute

### ✔ Tag（PI Point）

* 所属：PI Data Archive
* 本质：**原始时序数据**
* 特点：

  * 一定落库 ✅
  * 无业务语义 ❌

👉 类似：InfluxDB measurement

---

### ✔ Attribute

* 所属：PI AF
* 本质：**资产的属性（语义容器）**

👉 可以来自：

| 来源         | 是否落库 |
| ---------- | ---- |
| Tag        | ✅    |
| 静态值        | ❌    |
| Expression | ❌    |
| Analysis   | 可选   |

---

👉 一句话：

> **Attribute ≠ 数据，而是“数据或计算的载体”**

---

# 3️⃣ 指标 / 状态 / 属性（关键结论）

👉 在 PI 里：

```
指标 = 状态 = 属性 = Attribute
```

区别只在**业务语义**：

* 指标：Efficiency、KPI
* 状态：Running、Alarm
* 属性：RatedPower

---

# 4️⃣ Expression / Analysis / Attribute 关系

```
Expression（公式）
   ↓
Analysis（执行）
   ↓
Attribute（结果）
```

---

# 5️⃣ 是否落库（最容易考点）

| 类型                    | 是否落库  |
| --------------------- | ----- |
| Tag                   | ✅ 一定  |
| Attribute（引用Tag）      | ✅     |
| Analysis结果            | ✅ 或 ❌ |
| Expression（on-demand） | ❌     |

---

👉 核心理解：

> **PI 既支持“存指标”，也支持“算指标”**

---

# 6️⃣ 一句话总总结（最重要）

> **Tag 是“数据”，Attribute 是“业务语义”，Expression/Analysis 是“让数据变成指标的规则”**

---

# 7️⃣ 对标你系统（超简版）

```
PI Tag        ≈ 时序数据
PI Attribute  ≈ 语义字段 / 指标定义
PI Analysis   ≈ 流计算 / 指标引擎
PI EventFrame ≈ 事件表
```
