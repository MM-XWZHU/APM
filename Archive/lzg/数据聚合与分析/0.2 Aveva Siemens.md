# Aveva PI/..., Siemens WinCC/...
 **AVEVA PI System**（包含 PI Asset Framework 和 PI Analytics）在 2021 年已经被 AVEVA 收购。因此，AVEVA 现在的策略是将 SCADA（如 Wonderware/System Platform）与 PI System 的数据管理和分析能力深度集成。

西门子作为工业自动化领域的另一大巨头，同样拥有从 SCADA 到资产管理、再到高级分析的完整产品组合。以下是西门子与 AVEVA PI System 功能相对应的产品：

### 🗂️ 对应 PI Asset Framework (资产框架)

西门子的对应产品主要是 **SIMATIC WinCC / PCS 7 Plant Asset Management (PAM)** 以及更上层的 **Siemens Xcelerator** 产品组合。

*   **SIMATIC WinCC / PCS 7 PAM:**
    *   这个系统可以直接集成在 SIMATIC WinCC SCADA 系统或 SIMATIC PCS 7 过程控制系统中。
    *   它提供了一个统一的平台，用于监控和管理工厂的所有关键资产，包括阀门、仪表、电机、泵、驱动器等。
    *   它将过程控制信息与资产管理信息无缝集成，可以持续监控资产状态，降低故障风险，提高设备可用性。

*   **Siemens Xcelerator (资产生命周期管理):**
    *   这是一个更广泛的数字化业务平台，其中包含了用于改善资产生命周期管理的解决方案。
    *   它可以帮助企业提高资产绩效和可持续性，同时降低成本，实现更可预测的运营结果。

### 📈 对应 PI Analytics (分析)

西门子的分析功能主要通过其 **SCADA 系统内置的分析能力** 和 **更高级的工业智能软件** 来实现。

*   **SIMATIC SCADA 系统分析功能:**
    *   西门子的 SCADA 系统（如 WinCC Unified）本身就具备强大的分析功能。
    *   它可以将采集到的实时数据转化为有价值的资产，通过图表、报告等工具帮助用户发现隐藏的生产潜力，做出有针对性的决策，从而提高效率和生产力。

*   **SIMICAS 设备远程运维平台:**
    *   这是一个更侧重于数据深度分析和 AI 算法的平台。
    *   它基于采集的设备数据，利用 AI 进行深度算法分析，可以实现远程运维、优化设备工艺和能耗，并提供主动服务。这类似于 AVEVA 的预测性维护和分析功能。

### 📌 总结对比

为了让你更清晰地理解，可以参考下面的对比表：

| 功能领域 | AVEVA 产品 | 西门子对应产品 |
| :--- | :--- | :--- |
| **基础 SCADA** | AVEVA System Platform / Wonderware | SIMATIC WinCC / PCS 7 |
| **资产框架与管理** | PI Asset Framework | SIMATIC WinCC / PCS 7 PAM / Siemens Xcelerator |
| **数据分析与智能** | PI Analytics / AVEVA Predictive Analytics | SIMATIC SCADA 分析功能 / SIMICAS 平台 |

总而言之，西门子不仅提供基础的 SCADA 系统，同样也构建了从资产管理和数据分析到远程运维的完整上层应用生态，与 AVEVA 的产品线形成了直接竞争。

# 🧠 一句话先给结论

> Siemens 没有一个“完全等价 PI Analytics”的单一模块，
> 而是通过 **SCADA + Historian + Reporting + 脚本/IT集成** 组合实现

---

# 一、先建立一个“对标框架”（最关键）

| PI Analytics 概念 | Siemens 对应实现       |
| --------------- | ------------------ |
| Tag             | WinCC Tag          |
| Attribute（语义）   | 无原生 → 通过结构/命名/脚本   |
| Expression      | WinCC 脚本 / 计算 / 变量 |
| Rollup          | 脚本 / 报表 / SQL      |
| Event Frame     | Alarm / Event / 日志 |
| SQC             | 报表 / 外部分析          |

---

👉 核心差异：

```text
PI：内置“语义+计算引擎”
Siemens：偏“数据采集+展示+外部分析”
```

---

# 二、分层来看 Siemens 是怎么实现的

---

# 🧱 1️⃣ 数据层（= PI Tag）

## 对应：WinCC Tag

在 SIMATIC WinCC 中：

* 采集 PLC / OPC 数据
* 实时变量（Tag）

👉 官方说明：

* 支持数据采集、监控、归档、报警等 ([Siemens Digital Industries Software][1])

---

## 📌 对标

```text
PI Tag ≈ WinCC Tag
```

👉 这一层是完全对等的

---

# 🧠 2️⃣ “Expression能力”（PI Analytics核心）

## 在 Siemens 里没有统一模块 → 分散实现

---

## ✔ 方式1：WinCC 脚本（最接近 Expression）

支持：

* VBScript / C Script / JS（Unified）
* 在变量变化时执行

---

### 示例（等价 PI Expression）

PI：

```text
Efficiency = Output / Input
```

WinCC：

```vb
Efficiency = Output / Input
```

（写在脚本或内部变量）

---

## 📌 本质

👉 WinCC Script =

```text
PI Expression + Trigger（弱化版）
```

---

## ✔ 方式2：内部变量（Internal Tag）

* 定义计算变量
* 周期更新

👉 类似：

```text
Attribute（计算型）
```

---

## ⚠️ 关键差异

| PI      | Siemens |
| ------- | ------- |
| 原生表达式引擎 | ❌       |
| 统一模型    | ❌       |
| 模板复用    | 弱       |

👉 所以：

> Siemens 的 Expression 能力 = **“脚本化实现”**

---

# 🏭 3️⃣ Rollup（层级聚合）

---

## ✔ 在 Siemens 的实现方式

### 方式1：脚本聚合

```text
TotalPower = Pump1 + Pump2 + Pump3
```

---

### 方式2：报表/SQL

通过：

* Historian
* SQL 查询

---

### 方式3：报表系统

使用：

* SIMATIC Information Server

👉 用于 KPI 汇总、趋势分析 ([Siemens Digital Industries Software][2])

---

## 📌 对比

| PI Rollup  | Siemens |
| ---------- | ------- |
| 自动层级       | ❌       |
| Children语义 | ❌       |
| 结构驱动       | ❌       |
| 实现方式       | 手写      |

---

👉 本质：

> Siemens Rollup = “人为写聚合逻辑”

---

# 🧾 4️⃣ Event Frame（事件建模）

---

## ✔ 在 Siemens 中的对应

### 1. Alarm（报警）

* 条件触发
* 带时间

---

### 2. Event Logging

* 操作记录
* 状态变化

---

👉 WinCC 提供：

* 灵活报警配置
* 事件记录 ([Siemens Digital Industries Software][1])

---

## ✔ 扩展（更接近 PI）

通过：

* Historian + 报表
* 或外部系统

---

## 📌 差异

| PI Event Frame | Siemens |
| -------------- | ------- |
| 事件对象           | ❌       |
| 持续时间           | ❌       |
| 属性扩展           | ❌       |

---

👉 本质：

> Siemens 只有“事件记录”，没有“事件建模”

---

# 📊 5️⃣ Historian（非常关键）

## 对应：

* SIMATIC Process Historian

👉 功能：

* 长期数据归档
* 支持分析 ([Siemens Digital Industries Software][2])

---

## 📌 对标

```text
PI Data Archive + 部分 Analytics
```

---

# 📈 6️⃣ 报表 / KPI（替代 Analytics）

---

## 使用：

* Information Server
* Excel 报表
* BI工具

---

👉 能做：

* KPI
* 趋势
* 聚合分析

---

👉 官方：

* 提供 dashboard 和报表分析能力 ([Siemens Digital Industries Software][2])

---

## 📌 本质

```text
PI Analytics（实时）
→ Siemens（离线/报表）
```

---

# 🔗 7️⃣ IT/高级分析（关键补位）

Siemens 强项在这里：

---

## ✔ 工具

* IndustrialDataBridge
* OPC UA / MQTT
* 外部系统（Python / 云）

👉 支持 OT/IT 集成 ([Siemens Digital Industries Software][3])

---

## 📌 作用

👉 把 Analytics 外移：

```text
WinCC → 数据 → IT系统（Flink / AI）
```

# 三、用一个完整场景对比（最清楚）

---

## 🎯 场景：设备效率分析

---

### ✔ 在 PI

```text
Tag → Attribute → Expression → Event Frame
```

---

### ✔ 在 Siemens

```text
Tag（WinCC）
   ↓
脚本计算 Efficiency
   ↓
写入 Tag / Historian
   ↓
报表分析
   ↓
报警（简单事件）
```

---

👉 差异：

| 能力     | PI | Siemens |
| ------ | -- | ------- |
| 实时指标引擎 | ✅  | ⚠️（脚本）  |
| 语义模型   | ✅  | ❌       |
| 事件建模   | ✅  | ❌       |
| 分析统一性  | ✅  | ❌       |

---

# 四、最本质差异（非常关键）

## 🧠 PI 思路

```text
数据 → 语义 → 分析（内建）
```

---

## 🧠 Siemens 思路

```text
数据 → 可视化 → 分析（外挂）
```

---

# 🔥 五、最终总结（给你记的）

---

## 🥇 第一条

> **PI Analytics = 内置分析引擎**

---

## 🥈 第二条

> **Siemens = SCADA + Historian + 报表 + 脚本拼出来**

---

## 🥉 第三条（最关键）

> **PI 是“模型驱动分析”，Siemens 是“数据驱动展示 + 外部分析”**
