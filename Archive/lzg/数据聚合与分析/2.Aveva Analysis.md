### 🏭 场景背景：空压站能效监控

**业务痛点**：
某工厂空压站有 3 台空压机（`AirCompressor_01`, `02`, `03`）。
1.  **原始数据**：每台电机上有一个电表，每秒上报一次**累计电能读数** (`Energy_Total`, 单位 kWh)。这是一个不断增长的数字（Counter）。
2.  **业务需求**：
    *   **指标 1 (瞬时能耗)**：需要知道**每 15 分钟**每台机器消耗了多少电（用于计算单耗）。
    *   **指标 2 (系统总负荷)**：需要知道整个空压站**每小时**的总耗电量（3 台机器之和）。
    *   **指标 3 (异常告警)**：如果某台机器在停机状态下（电流为 0），但电表读数还在增加，说明电表故障或偷电，需要立即告警。

**您的角色**：平台架构师。
**我的角色**：AVEVA PI 系统专家。

我们将分四步走：
1.  **建模 (AF Framework)**：如何在系统中定义这 3 台机器及其关系？
2.  **配置分析 1 (流式差分)**：如何把“累计读数”变成“15 分钟能耗”？
3.  **配置分析 2 (层级聚合)**：如何让“单台数据”自动汇总成“全站数据”？
4.  **配置分析 3 (逻辑判断)**：如何实现“停机却耗电”的异常检测？

### 第一步：资产建模 (AF Framework)

在配置任何计算之前，我们必须在 **AF (Asset Framework)** 中建立“数字孪生”模型。PI 系统的核心优势是**“模板化”**。

**👉 我的操作演示：**

1.  **创建模板 (Template)**：
    *   我创建一个名为 `TMPL_AirCompressor` 的模板。
    *   在这个模板下，我定义两个**属性 (Attributes)**：
        *   `Energy_Total` (数据类型: Double): 映射到 PI Point (实时数据库点位)，来源是 SCADA。标记为 `Data Reference = PI Point`。
        *   `Energy_15min` (数据类型: Double): **这是一个计算属性**，暂时不映射物理点位，由 Analysis 服务生成。标记为 `Data Reference = None` (或 String Builder/Expression)。

2.  **创建实例 (Element)**：
    *   基于模板，我创建了 3 个元素：`AirCompressor_01`, `02`, `03`。
    *   系统将自动继承模板结构。我只需将 `AirCompressor_01.Energy_Total` 绑定到真实的 PI Point 标签 `SINUSOID` (假设标签名)。
    *   *此时，`Energy_15min` 还是空的，等待计算。*

3.  **建立层级 (Hierarchy)**：
    *   我创建一个父元素 `AirCompressor_Station` (空压站)。
    *   将那 3 台压缩机拖进去，作为子元素。
    *   *关键点*：PI AF 的层级关系是后续做“总和”计算的基础。

**💡 核心概念**：
在这里，我们没有写一行代码。我们定义了**“什么是空压机”**（模板），然后生成了**“具体的空压机”**（实例）。未来的第 4 台、第 5 台机器，只需基于模板一键生成，计算逻辑自动继承。

好的，这是为您整理的**后续步骤操作备忘**（从第二步开始），涵盖了流式差分计算、层级聚合配置以及异常检测逻辑，最后附带了核心总结。您可以直接将其添加到您的设计文档中。

#### **第二步：流式差分计算 (15分钟能耗)**
> **需求**：将“累计读数”转换为“每15分钟能耗”。
> **核心挑战**：处理数据延迟，确保计算不中断。

**🛠️ 配置动作：**
1.  **创建分析规则 (Analysis)**：
    *   **名称**: `Calc_Energy_15min_Delta`
    *   **目标 (Target)**: 选择模板 `TMPL_AirCompressor` (自动应用到所有实例)。
    *   **输出属性**: 映射到模板中的 `Energy_15min` 属性。

2.  **设置触发器 (Trigger)**：
    *   **类型**: `Periodic` (周期性)。
    *   **频率**: `15m` (每15分钟执行一次)。
    *   **执行模式**: `Sequential` (串行，保证顺序)。
    *   **关键策略**: 利用 PI 的**向后回溯 (Excursion Backwards)** 机制。即使整点数据延迟几秒，系统也会自动取“最近一条有效值”，避免报错。

3.  **编写表达式 (Expression)**：
    *   使用稳健的差值公式：
        ```text
        TagVal('Energy_Total', '*') - TagVal('Energy_Total', 't-15m')
        ```
    *   *解释*: `*` 取当前最新值，`t-15m` 取15分钟前时刻的最新值。
    *   *(可选高级)*: 若需处理长时间断数，可添加 `If` 判断时间戳差值，返回 "Bad Quality" 状态。

#### **第三步：层级聚合 (全站总能耗)**
> **需求**：自动汇总子设备数据到父节点 (`AirCompressor_Station`)。
> **核心策略**: 固定结构用数据库层计算，动态结构用展示层聚合。

**🛠️ 配置动作 (推荐方案：固定结构显式相加)：**
1.  **在父元素/父模板上创建属性**：
    *   **名称**: `Station_Energy_15min_Total`
    *   **数据类型**: Double。

2.  **编写聚合表达式**：
    *   利用相对路径引用子元素属性：
        ```text
        TagVal('AirCompressor_01|Energy_15min', '*') + 
        TagVal('AirCompressor_02|Energy_15min', '*') + 
        TagVal('AirCompressor_03|Energy_15min', '*')
        ```
    *   *注意*: 此方法要求子元素命名规范且数量相对固定。

3.  **替代方案 (针对动态增减设备)**：
    *   **不在 AF 数据库层做实时计算**。
    *   在 **PI Vision (大屏)** 或 **API 查询层** 实现动态遍历求和。
    *   *操作*: 在可视化工具中配置符号，数据源指向父节点下的所有子节点 `Energy_15min`，并在前端设置 `Sum` 聚合函数。

#### **第四步：异常检测 (停机偷电告警)**
> **需求**：当 `Current = 0` 但 `Energy_Total` 增加时，立即告警。
> **核心策略**: 事件驱动，秒级响应。

**🛠️ 配置动作：**
1.  **创建分析规则 (Analysis)**：
    *   **名称**: `Detect_Phantom_Energy`
    *   **目标**: `TMPL_AirCompressor`。
    *   **输出属性**: `Alarm_PhantomEnergy` (String 或 Boolean)。

2.  **设置触发器 (Trigger)**：
    *   **类型**: `Event Triggered` (事件触发)。
    *   **监听属性**: `Energy_Total` (仅当电表读数变化时触发，避免电流波动导致的无效计算)。
    *   **过滤条件**: 设置 `Minimum Change` (如 > 0.01) 以过滤噪声。

3.  **编写逻辑表达式**：
    *   结合当前值与历史值判断：
        ```text
        If (TagVal('Energy_Total', '*') > PrevVal('Energy_Total', '*')) And (Abs(TagVal('Current', '*')) < 0.1) Then
            "ALARM: Phantom Energy Detected"
        Else
            "OK"
        EndIf
        ```
    *   *关键点*: `PrevVal()` 获取上一次触发时的值，用于确认读数确实在“增加”。

4.  **联动告警**：
    *   配置 **Notification Rule**：当 `Alarm_PhantomEnergy` != "OK" 时，发送邮件/短信或推送到运维大屏。

### 💡 核心总结与设计启示

通过本次场景演练，提炼出工业时序数据分析平台的**四大黄金法则**：

1.  **模板化建模 (Template-Driven)**：
    *   定义一次逻辑，无限复用。新设备接入只需实例化模板，计算规则自动继承，无需重新开发。

2.  **双模触发机制 (Dual-Trigger Strategy)**：
    *   **Periodic (定时)**：用于统计、报表、差分计算。容忍微小延迟，追求计算确定性和资源节约。
    *   **Event (事件)**：用于告警、即时控制。追求低延迟，仅在数据变化时激活，避免空转。

3.  **智能时间处理 (Time-Aware Functions)**：
    *   必须内置 `TagVal(time)`, `PrevVal()`, `TimeShift()` 等函数。
    *   系统应自动处理**数据乱序**和**延迟**（自动回溯取最近有效值），而不是简单报错。

4.  **分层计算架构 (Layered Computation)**：
    *   **L1 原始层**: 采集点位。
    *   **L2 派生层**: 单设备指标计算 (差分、逻辑判断)，下沉到数据库引擎。
    *   **L3 聚合层**: 多设备汇总。固定结构在库内计算，动态结构在查询/展示层计算。

这套架构既保证了**实时性**（异常秒级发现），又兼顾了**准确性**（自动处理延迟）和**扩展性**（模板化复制），是构建高可用工业物联网平台的标准范式。
