# 🧩 场景：光伏 + 储能系统中的“逆变器停机事件分析”

## 🎯 业务背景

在一个光伏电站中：

* 设备：逆变器（Inverter）
* 数据：

  * `Power`（输出功率）
  * `Status`（运行状态）
  * `AlarmCode`（故障码）

👉 运维人员关心：

1. 设备什么时候停机？
2. 每次停机持续多久？
3. 停机期间损失多少发电量？
4. 停机原因是什么？

---

# ❗ 如果不用 Event Frame 会怎样？

你只能：

* 用 SQL 查：

  ```
  Power = 0 的时间段
  ```
* 手动拼接区间
* 很难：

  * 标准化
  * 复用
  * 做统计

👉 这是典型“时序库能查，但不好建模”的问题

---

# ✅ 使用 Event Frame 的思路

## 一句话：

👉 **把“停机”变成一个“对象（事件）”，而不是一堆点数据**

---

# 🧱 Step 1：定义事件（Analysis）

### 条件（Trigger）

```
当 Power < 10 kW 持续 5 分钟
→ 判定为停机开始
```

```
当 Power > 10 kW
→ 判定为停机结束
```

---

# 🧠 Step 2：创建 Event Frame

每次停机会生成一个 Event：

```
Event Frame:
- Name: Inverter_001_Downtime
- Start: 10:05
- End: 10:32
- Duration: 27 min
```

👉 这就是 PI Analytics 自动生成的“事件对象”

---

# 🏷️ Step 3：给事件加属性（关键价值）

Event Frame 不只是时间区间，还可以带数据：

### ✔ 基础属性

* Duration（持续时间）
* StartTime / EndTime

---

### ✔ 计算属性（重点）

#### 1️⃣ 停机损失电量

```
Loss = TagTot(ExpectedPower - ActualPower)
```

---

#### 2️⃣ 停机原因

```
Cause = AlarmCode
```

---

#### 3️⃣ 停机前温度

```
Temp_before = TagVal(Temperature, EventStart - 5min)
```

---

👉 结果变成：

```
Event Frame:
- Start: 10:05
- End: 10:32
- Duration: 27 min
- Loss: 120 kWh
- Cause: Overheat
- Temp_before: 85°C
```

---

# 📊 Step 4：如何用这些 Event Frame？

## 1️⃣ 报表（最常见）

你可以直接做：

* 每天停机次数
* 平均停机时长
* 总损失电量

👉 不需要再拼时间区间

---

## 2️⃣ 排序分析（找问题设备）

```
Top 10 停机损失最大设备
```

---

## 3️⃣ 运维分析

* 哪种故障最多？
* 哪个设备最不稳定？

---

## 4️⃣ BI / AI 输入

Event Frame 是非常好的特征数据：

* 用于预测维护
* 用于异常分类

---

# 🔄 对比：Event Frame vs 普通时序查询

| 能力    | 普通时序  | Event Frame |
| ----- | ----- | ----------- |
| 找停机区间 | ❌ 复杂  | ✅ 自动        |
| 持续时间  | ❌ 需计算 | ✅ 自带        |
| 事件属性  | ❌ 无   | ✅ 有         |
| 复用    | ❌     | ✅           |
| 业务语义  | ❌     | ✅           |

# 🧠 再给你一个更高级的场景（储能）

## ⚡ 场景：电池充放电循环（Cycle）

👉 定义一个“Cycle Event”：

### 开始：

```
SOC 从 <20% 上升
```

### 结束：

```
SOC 达到 >80%
```

---

### 每个 Event Frame：

```
Cycle:
- Start: 08:00
- End: 10:30
- Energy Charged: 500 kWh
- Efficiency: 92%
- Max Temp: 45°C
```

---

👉 这在储能运维中非常关键：

* 电池寿命分析
* 充放电效率
* 异常 cycle

---

# 🚀 本质总结（非常重要）

👉 Event Frame 做了一件关键的事：

```
把“连续时间序列”
→ 转换为
“离散业务事件”
```

---

# 📌 用一句话理解

> 如果 PI Tag 是“原始数据”，
> 那 Event Frame 就是“业务日志（Business Event Log）”

---

```
        ↓
存储（ClickHouse / ES）
```
