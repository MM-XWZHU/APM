
# 🧠 一句话先记住

> **Rollup = 把“多个子资产的属性”按规则汇总成“父资产的指标”**

---

# 🧩 它在 PI 里的位置

```id="h6l86n"
子设备 Attribute →（Rollup）→ 父设备 Attribute
```

* 发生在：**AF（资产层）**
* 本质：**层级聚合（Hierarchy Aggregation）**

---

# ⚙️ 场景1：生产线产量汇总（最经典）

## 🎯 需求

一个工厂有3条产线，每条都有产量：

```id="nq5r0q"
Line1.Output = 100
Line2.Output = 120
Line3.Output = 80
```

👉 想要：工厂总产量

---

## ✅ Rollup 定义

```id="vtp7fl"
Plant.TotalOutput = Sum(Children.Output)
```

---

## ✅ 结果

```id="1y8brd"
Plant.TotalOutput = 300
```

---

## 📌 本质

👉 不用写 SQL / JOIN
👉 自动跟随资产结构变化

---

# ⚡ 场景2：能耗汇总（能源系统）

## 🎯 需求

每个设备有功率：

```id="m6x1zk"
Pump1.Power = 50
Pump2.Power = 70
Pump3.Power = 30
```

👉 计算车间总功率

---

## ✅ Rollup

```id="6wsl4q"
Workshop.TotalPower = Sum(Children.Power)
```

---

## 📌 关键点

* 可以实时更新（随子设备变化）
* 可继续往上汇总（厂级）

---

# 🔋 场景3：储能系统（你这个行业很典型）

## 🎯 需求

多个电池柜：

```id="if56nz"
Battery1.SOC = 80%
Battery2.SOC = 60%
Battery3.SOC = 70%
```

👉 想要整体 SOC

---

## ❗ 注意（这里是关键）

不能直接平均，需要**加权**

---

## ✅ Rollup（加权平均）

```id="tfzhcg"
Plant.SOC = Sum(SOC * Capacity) / Sum(Capacity)
```

---

## 📌 本质

👉 Rollup 不只是 Sum
👉 可以结合 Expression 做复杂逻辑

---

# 🏭 场景4：设备健康评分（高级一点）

## 🎯 需求

每台设备有健康评分：

```id="vfx5r1"
Pump1.Health = 90
Pump2.Health = 70
Pump3.Health = 80
```

---

## ✅ Rollup

```id="v8w1n3"
Line.Health = Avg(Children.Health)
```

---

或更实际：

```id="d0nq3m"
Line.Health = Min(Children.Health)
```

👉 用最差设备代表整体

---

# 🚨 场景5：报警统计（配合 Event Frame）

## 🎯 需求

统计一个车间的报警次数

---

## 方法

* 每个设备：

  * Event Frame Count

---

## ✅ Rollup

```id="p2ndb4"
Workshop.AlarmCount = Sum(Children.AlarmCount)
```

---

# 🔄 Rollup vs Expression（关键区别）

| 维度   | Expression   | Rollup            |
| ---- | ------------ | ----------------- |
| 输入   | 任意 Attribute | **子资产 Attribute** |
| 作用   | 单设备计算        | **跨层级汇总**         |
| 典型   | Efficiency   | TotalOutput       |
| 依赖结构 | ❌            | ✅ AF层级            |

---

# 🧠 一个非常关键的理解

## Rollup 其实是“带结构的 Expression”

你可以理解为：

```id="bqvztb"
Rollup = Expression + 层级（Children）
```

---

# ⚠️ 是否落库？

| 情况                 | 是否落库  |
| ------------------ | ----- |
| Rollup → 写 PI Tag  | ✅     |
| Rollup → Attribute | ❌（常见） |

---

👉 实际中：

* KPI → 常落库
* 临时指标 → 不落库

---

# 🧩 和你系统的映射（重要）

如果你用 InfluxDB：

| PI Rollup   | 你系统           |
| ----------- | ------------- |
| Children 汇总 | group by / 聚合 |
| 层级结构        | 设备模型 / 维度     |
| 自动更新        | 流计算           |

---

👉 本质区别：

```id="k17a0j"
SQL:
SELECT SUM(power) FROM table GROUP BY workshop

Rollup:
Workshop.Power = Sum(Children.Power)
```

👉 PI 是“模型驱动”，不是“查询驱动”

---

# 🔥 最核心总结（记住这三条）

---

## 🥇 第一条

> **Rollup = 从“设备级” → “系统级”的自动汇总**

---

## 🥈 第二条

> **它依赖 AF 层级结构，而不是 SQL 分组**

---

## 🥉 第三条

> **Rollup 本质是“结构化聚合逻辑”，不是一次查询**
