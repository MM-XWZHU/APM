下面我用**多个真实工业场景**来讲清楚 PI Analytics 里 **Expression（表达式）到底是什么、解决什么问题、为什么重要**——你可以把它理解为：
👉 **“工业语义层里的计算公式 + 实时执行逻辑”**

---

# 一、先给你一句“本质定义”（非常关键）

> **Expression = 用输入数据（Tag/Attribute）+ 函数 + 运算规则 → 生成一个新属性（指标/状态）**

* 可以包含：

  * 运算符（+ - * /）
  * 函数（Avg / Tot / StDev）
  * 逻辑（>、IF）
* 输出：

  * 一个 Attribute 或 PI Tag

👉 官方描述本质：
Expression Analysis 是“用函数、操作符和输入值计算输出值，并映射到 AF 属性或 PI Tag” ([YouTube][1])

---

# 二、从“简单到复杂”的多个真实场景

我给你分 4 类场景，你会非常清楚 Expression 的边界在哪里。

---

# 🧪 场景1：最基础 —— 指标计算（KPI）

## 🎯 问题

计算设备效率：

```
效率 = 实际产量 / 理论产量
```

---

## ✅ Expression 写法

```text
Efficiency = Output / DesignCapacity
```

---

## 💡 关键理解

* Input：

  * Output（实时产量）
  * DesignCapacity（额定能力）
* Output：

  * Efficiency（新指标）

---

## 📌 本质

👉 Expression 在这里 =
**“指标定义语言”**

---

# ⚙️ 场景2：状态识别（比时序库强很多）

## 🎯 问题

判断设备是否运行：

* Power > 50 → Running
* 否则 → Stop

---

## ✅ Expression

```text
Running = Power > 50
```

或：

```text
Running = If Power > 50 Then 1 Else 0
```

---

## 💡 关键点

* 输出是 **Boolean / 状态**
* 可以作为：

  * Event Frame 输入
  * 告警触发条件

---

## 📌 本质

👉 Expression 在这里 =
**“规则引擎（Rule Engine）”**

---

# 🏭 场景3：工艺计算（时间窗口 + 函数）

## 🎯 问题

计算过去1小时平均温度

---

## ✅ Expression

```text
AvgTemp = TagAvg(Temperature, '*-1h', '*')
```

---

## 💡 关键点

* `TagAvg` 是 PI 内置函数
* `*-1h` → 当前时间往前1小时

---

## 📌 本质

👉 Expression 在这里 =
**“时序计算 DSL（比 SQL 更工业化）”**

---

# ⚡ 场景4：复杂逻辑（工业真正价值）

## 🎯 场景：检测“异常能耗”

逻辑：

* 设备运行中
* 流量低
* 功率高

👉 判定：可能故障

---

## ✅ Expression

```text
Abnormal = (Power > 100) AND (Flow < 20) AND (Running = 1)
```

---

## 💡 关键点

这在时序库里很难直接表达：

* 需要 JOIN
* 需要时间对齐
* 需要复杂查询

---

## 📌 本质

👉 Expression 在这里 =
**“工业语义规则表达能力”**

---

# 🔋 场景5：储能系统（贴近你业务）

## 🎯 问题：计算充放电效率

---

## ✅ Expression

```text
Efficiency = EnergyOut / EnergyIn
```

---

## 🎯 问题：识别充电状态

```text
Charging = Power < 0
```

---

## 🎯 问题：识别一个 Cycle（供 Event Frame 用）

```text
CycleStart = (SOC < 20) AND (dSOC/dt > 0)
```

---

## 📌 本质

👉 Expression 是 Event Frame 的“输入逻辑”

---

# 🧠 场景6：跨设备计算（AF 的优势）

## 🎯 问题

计算整个车间总产量：

---

## ✅ Expression

```text
TotalProduction = Sum(Unit1.Output, Unit2.Output, Unit3.Output)
```

---

## 💡 关键点

* 跨 Element
* 用 AF 模型组织

👉 这是普通时序库很难优雅实现的 ([PISharp][2])

---

# 🧩 场景7：On-demand Expression（高级）

## 🎯 问题

有些指标不想落库，只在查询时计算

---

## ✅ 方式

* Attribute Data Reference = Analysis
* Expression 不写入 PI Tag

---

## 💡 特点

* 查询时才计算
* 在客户端执行 ([AVEVA Community][3])

---

## 📌 本质

👉 Expression 也可以是：

**“虚拟指标（Virtual Metric）”**

---

# 三、把所有场景总结成一个统一模型

## Expression 的统一结构：

```text
Output = f(Input1, Input2, ..., 时间窗口, 逻辑规则)
```

---

## 可以覆盖的能力：

| 类型  | Expression 能做什么 |
| --- | --------------- |
| 指标  | KPI计算           |
| 状态  | Running / Stop  |
| 统计  | Avg / Sum       |
| 逻辑  | IF / AND        |
| 时间  | 时间窗口            |
| 跨资产 | 汇总              |

---

# 四、和你问题最关键的一点（本质对比）

你之前在问：

> 时序库已经能聚合，还需要 metrics 吗？

---

## 用 Expression 视角回答：

### ❌ 时序库（Influx）

```sql
SELECT mean(temp) FROM ...
```

👉 是：

* 查询语言
* 临时计算

---

### ✅ PI Expression

```text
AvgTemp = TagAvg(Temperature, '*-1h', '*')
```

👉 是：

* 持续运行
* 业务定义
* 可复用
* 可触发事件

---

# 🔥 最关键区别（一定要理解）

| 维度   | SQL | Expression |
| ---- | --- | ---------- |
| 执行方式 | 查询时 | 持续/触发      |
| 语义   | 无   | 有（AF）      |
| 复用   | 低   | 高          |
| 业务建模 | 弱   | 强          |

---

# 五、一个非常重要的总结（工业经验）

👉 Expression 其实做了三件事：

```text
1. 把“原始数据” → “业务指标”
2. 把“计算逻辑” → “可复用资产”
3. 把“查询行为” → “持续计算系统”
```

---

# 六、一句话总结（最重要）

> Expression 的本质不是“公式”，而是
> 👉 **工业场景下的“实时业务逻辑语言（Real-time Business Logic DSL）”**
