

# IBM Maximo Application Suite 核心模块功能深度解析

## 1. Maximo Manage（企业资产管理/EAM核心平台）

### 1.1 平台定位与核心价值

#### 1.1.1 作为IBM Maximo Application Suite的基石模块

**Maximo Manage**是IBM Maximo Application Suite（MAS）的**核心基石模块**，承载着整个套件的企业资产管理（EAM）功能。作为IBM近40年资产管理领域技术积累的集大成者，Manage模块将传统Maximo EAM系统的成熟功能与现代化云原生架构深度融合，构建了面向数字化转型的统一资产管理平台  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

从技术架构演进来看，Manage模块经历了从单体应用到容器化微服务的重大转型。MAS 8.11版本作为长期支持版本（Long Time Supported release），将Manage模块全面重构为基于**Red Hat OpenShift容器平台**的部署架构，支持本地数据中心、私有云、公有云（IBM Cloud、AWS、Azure）以及混合云等多种部署模式  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这种云原生设计带来了三大核心优势：**弹性扩展能力**（根据业务负载自动调整资源）、**高可用保障**（容器编排实现故障自动恢复）、以及**持续交付能力**（快速部署新功能和安全补丁）。

Manage模块的基石地位体现在其与其他MAS模块的**数据主从关系**上。Monitor采集的IoT数据、Health计算的健康评分、Predict生成的预测结果，最终都需要与Manage中的资产主数据、工单系统、维护计划进行关联，才能形成完整的闭环资产管理流程。产品描述明确指出，Manage模块通过"共享数据和工作流"实现跨模块协同，为用户提供"更好的用户体验"  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这种设计确保了数据一致性和业务流程的连贯性，避免了传统多系统集成中的信息孤岛问题。

#### 1.1.2 整合传统EAM功能与现代化资产管理能力

Manage模块的核心价值在于其对**传统EAM深度功能**与**现代化智能能力**的有机融合。传统功能方面，Manage完整保留了经过数十年行业验证的经典EAM能力，包括资产台账管理、预防性维护调度、工单全生命周期管理、库存采购控制等。现代化能力方面，Manage通过三大技术支柱实现了质的飞跃：

| 技术支柱 | 核心能力 | 业务价值 |
|:---|:---|:---|
| **人工智能（AI）** | 智能工单优先级排序、资源优化配置、预测性维护触发 | 提升决策效率30%以上 |
| **物联网（IoT）集成** | 实时传感器数据接入、条件监控自动触发、状态驱动维护 | 从定期维护转向基于状态的维护 |
| **高级分析** | 嵌入式KPI仪表盘、趋势分析、成本优化建议 | 数据驱动的资产管理决策 |

MAS 8.11版本的一项重大战略调整是将原先分散的多个独立许可组件**统一整合到Manage模块**中，包括线性资产管理（Linear）、校准管理（Calibration）、移动应用（Mobile）、调度器（Scheduler）以及可靠性管理（Reliability）等  [(Maximo Secrets)](https://maximosecrets.com/ibm-maximo-manage-overview/) 。这一整合显著降低了企业的总体拥有成本（TCO），同时简化了部署和运维复杂度。值得注意的是，Reliability功能虽然在技术文档中被标记为"add-on"，但由于许可模式已统一为单一部件号，实际上可视为Manage模块的内置能力  [(Maximo Secrets)](https://maximosecrets.com/ibm-maximo-manage-overview/) 。

Manage模块采用**角色化应用设计**（Role-Based Applications），这是其现代化用户体验的核心特征。通过IBM的Graphite Framework和Carbon Design组件，系统仅向用户展示完成特定业务流程所需的字段和功能，大幅提升了操作效率  [(Maximo Secrets)](https://maximosecrets.com/ibm-maximo-application-suite-overview/) 。例如，技术人员看到的界面聚焦于工单执行和工时记录，而计划员界面则突出调度甘特图和资源负载视图，这种"千人千面"的设计显著降低了用户学习成本。

#### 1.1.3 支持企业级资产全生命周期管理

Manage模块的设计哲学贯穿资产从**规划、采购、安装、运行、维护到退役处置**的完整价值链，形成端到端的生命周期管理能力：

| 生命周期阶段 | 核心功能 | 关键应用 |
|:---|:---|:---|
| **规划阶段** | 资本项目管理、投资优化分析、资产模板定义 | 资产模板（Asset Templates）、项目（Projects） |
| **采购阶段** | 采购申请、供应商选择、合同管理、接收验收 | 采购申请（Purchase Requisitions）、采购订单（Purchase Orders）、收货（Receiving） |
| **运营阶段** | 实时状态监控、性能跟踪、运行数据记录 | 计量器（Meters）、条件监控（Condition Monitoring） |
| **维护阶段** | 预防性维护、纠正性维护、预测性维护、紧急维护 | 预防性维护（Preventive Maintenance）、工单跟踪（Work Order Tracking） |
| **退役阶段** | 资产处置、残值评估、环境合规、财务核销 | 资产状态管理、成本归集、处置流程 |

这种全生命周期管理能力在大型资本密集型行业尤为关键。以电力公用事业为例，变电站变压器等关键资产的设计寿命可达30-40年，期间需要经历多次大修、技术改造和性能升级。Manage模块通过完整的资产历史记录、维护成本追踪、性能趋势分析，帮助企业评估不同维护策略的经济性，优化资产更换时机，最大化资产投资回报  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2024/03/07-PACMUGC24_MAS_Update_IBM.pdf) 。产品描述中提到的**"资产投资分析"（Asset Investment Analysis）**功能，正是支持这类长期战略决策的专业工具。

### 1.2 核心功能域

#### 1.2.1 资产管理（Assets）

资产管理是Maximo Manage最基础也是最核心的功能域，其设计目标是建立企业资产的**单一真实数据源（Single Source of Truth）**。

**资产台账与主数据管理**构成了资产管理的数据基石。"资产"（Assets）应用用于存储资产编号及相应信息，包括父资产、位置、供应商、运行/停机状态以及每项资产的维护成本  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。系统支持高度灵活的资产层级结构，允许企业按照功能位置、系统-子系统-设备等维度组织资产树。资产主数据的设计遵循**ISO 14224**等国际标准，支持KKS编码、TAG编号等多种标识体系，确保与工程设计、运营维护、财务核算等不同业务领域的标识一致性。

**资产分类与层级结构管理**通过"分类"（Classifications）应用实现，该应用用于创建分类并建立项目、资产、位置、工单等的整体分类层次结构  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。分类体系支持多维度属性定义，企业可以为不同类别的资产定义特定的技术参数和管理属性。例如，旋转机械类资产可以定义转速、功率、轴承类型等属性，而电气设备类资产则可以定义电压等级、绝缘等级、防护等级等属性。这种精细化的资产画像为后续的维护策略制定、备件需求预测、性能基准建立奠定了基础。

**资产状态跟踪与条件监控**是Manage模块的差异化能力。系统通过"计量器"（Meters）应用添加或修改计量器定义，包括计量器名称以及描述计量器的一组属性；"计量器组"（Meter Groups）应用则用于定义计量器的逻辑分组，代表将多次一起使用的计量器集合  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。更为重要的是**"条件监控"（Condition Monitoring）**应用，该应用允许为资产定义**无限数量的测量点**，并指定报警限值以及达到这些限值后要执行的相关工作  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这一设计与Maximo Monitor的深度集成，使企业能够建立从简单计数器到复杂振动分析的多层次监控体系，实现从定期维护向基于状态的维护策略转型。

**故障代码体系与故障分析**通过"故障代码"（Failure Codes）应用实现，该应用用于构建和显示故障层次结构，帮助企业构建影响其资产和运营位置的故障的准确历史记录  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。故障代码体系通常按照**"故障现象-故障原因-修复措施"**的三层结构组织，支持RCM（以可靠性为中心的维护）分析所需的数据积累。系统还提供了"可靠性策略"（Reliability Strategies）应用，支持基于行业最佳实践的维护策略制定。MAS 8.11版本引入了由行业和领域专家开发的资产失效模式库，涵盖数百类资产的数万个潜在失效场景  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**备件关联与Spare Parts管理**建立了资产与库存的关联关系。系统支持在资产记录中定义关联备件，包括推荐备件、关键备件和可替换部件，信息涵盖物料编码、安装数量、存储位置、替代关系等。这一功能与库存管理模块深度集成，可以实时查询备件可用性，并在备件短缺时自动触发采购流程。对于**旋转资产（Rotating Assets）**的特殊处理机制，允许将整件设备（如电机、泵）作为库存项目管理，在维修场景中实现整件更换而非现场修复，大幅缩短停机时间。

**资产移动、调整与处置管理**覆盖了资产生命周期的末端流程。系统支持资产在企业内部的调拨、状态变更（如从在建转固、从运行到报废）以及相关的财务处理。资产模板（Asset Templates）的应用使得批量资产更新成为可能，显著提升了大规模资产管理场景下的操作效率  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

#### 1.2.2 工作管理（Work Management）

工作管理模块是Maximo Manage中**业务最密集、使用最频繁**的功能域，其核心目标是确保维护工作的高效计划、执行和跟踪。

**工单全生命周期管理**通过"工单跟踪"（Work Order Tracking）应用实现，覆盖工单的**创建、计划、调度、执行、验收和关闭**完整流程。系统支持多种工单类型，每种类型可配置不同的工作流和审批规则：

| 工单类型 | 触发机制 | 典型应用场景 |
|:---|:---|:---|
| **纠正性维护（Corrective Maintenance）** | 故障报告、条件监控告警、预测性维护触发 | 设备故障后的修复作业 |
| **预防性维护（Preventive Maintenance）** | 时间周期、计量表读数达标 | 定期保养、润滑、检查 |
| **预测性维护（Predictive Maintenance）** | Maximo Predict分析结果 | 基于状态趋势的提前干预 |
| **紧急维护（Emergency Maintenance）** | 安全事件、重大故障 | 需要立即响应的紧急情况 |

工单的创建来源极为灵活：可以手工创建、从服务请求（Service Request）转换、由预防性维护计划自动生成、由条件监控告警触发，或通过API从外部系统集成。这种多元化的工单生成机制确保了各类维护需求都能被及时捕获和合理处理。

**预防性维护计划（PM）制定与自动触发**是实现主动维护的关键机制。系统支持**基于时间**（日历周期或运行小时数）和**基于条件**（计量表读数或监测指标）两种触发模式。时间型PM可以设置为固定间隔（如每30天）或浮动间隔（如上次完成后30天）；条件型PM则与监控点关联，当监测指标达到设定阈值时自动触发。PM计划可以关联作业计划（Job Plan），实现维护内容的标准化和自动化。"主PM"（Master PM）功能支持维护策略的批量应用和统一更新，当维护需求变更时，只需更新主PM即可同步影响所有关联资产  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**工作请求管理与优先级排序**通过"服务请求"（Service Requests）应用及相关角色化应用实现。产品描述中列出了"创建服务请求"、"查看服务请求"、"搜索解决方案"等自助服务功能，以及面向服务台人员的"活动和任务"、"服务请求"、"解决方案"、"工单模板"等应用  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。服务请求允许任何授权用户（包括非维护人员）提交维护需求，系统自动路由到相应的维护团队进行评估和处理。请求可以关联资产、位置或系统，支持附件上传和详细描述。维护计划人员根据**资产关键性、故障影响、资源可用性**等因素对请求进行优先级排序，决定是立即处理、纳入计划还是暂缓。

**工单成本跟踪与工时记录**通过"人工报告"（Labor Reporting）和"快速报告"（Quick Reporting）应用实现。人工报告应用支持详细的工时、物料、工具消耗记录，而快速报告则针对简单场景提供简化的数据录入界面。成本数据实时归集到资产和位置，支持按资产、按部门、按工单类型、按时间段的多维度分析。系统支持多种工时记录方式：手工录入起止时间、计时器自动计算、或通过Maximo Mobile现场实时记录。

**外协服务与内部工单协同**方面，Manage模块通过"采购申请"、"采购订单"、"公司"、"公司主数据"等应用实现外部服务的采购管理。系统支持在工单中定义外协服务需求，自动生成采购申请和采购订单，跟踪供应商工作进度和成本。对于需要内外部协同的复杂项目，系统支持**工单层级结构**（Work Order Hierarchy），将总包工单分解为多个子工单，分别由内部团队或外部供应商执行，实现统一计划和分别执行。

#### 1.2.3 库存与采购管理（Inventory & Purchasing）

库存与采购管理模块确保维护活动所需物资和服务的**及时、经济供应**，同时通过精细化的库存控制降低资金占用。

**库存主数据与仓库管理**通过"项目主数据"（Item Master）、"服务项"（Services）、"库存"（Inventory）、"库房"（Storerooms）等应用实现。"项目主数据"应用维护企业所有库存物资的基本信息，包括编码、描述、分类、计量单位、计划参数等；"库房"应用定义物理存储位置及其属性，支持**多层级库位管理**（仓库-库区-货架-货位）。系统支持为同一物料在不同仓库设置不同的库存参数，适应差异化的管理需求。

**库存事务处理**涵盖收、发、转、盘点等全部操作，每种事务都有严格的流程控制和审批机制：

| 事务类型 | 核心应用 | 关键功能 |
|:---|:---|:---|
| **收货** | 收货（Receiving）、装运收货（Shipment Receiving） | 采购入库、调拨入库、退货入库，支持批次/序列号跟踪 |
| **发料** | 库存使用（Inventory Usage） | 工单发料、部门领用、销售出库，自动更新库存余额 |
| **转移** | 库存使用（Inventory Usage） | 仓库间调拨、货位调整，支持在途库存管理 |
| **盘点** | 盘点手册（Count Books）、库存盘点（Inventory Counting） | 周期盘点、循环盘点、全面盘点，盘点差异审批调整 |

MAS 8.11版本引入了专门的移动应用支持库存作业，包括"库存盘点"、"库存收货"、"发放与转移"等，显著提升了仓库作业的效率和准确性  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**库存成本核算与计价**支持多种成本计算方法：**标准成本法**（预设标准成本，差异单独分析）、**移动平均成本法**（动态计算平均成本）、以及**先进先出法（FIFO）**等。成本计算自动处理复杂场景：部分收货、分批发货、退货、调价等，确保财务账与实物账的一致性。

**采购申请、采购订单与供应商管理**实现了从需求产生到订单履行的完整采购流程。采购申请可以手工创建、由库存再订货点自动触发、或由工单预留自动生成。申请经过审批后转换为采购订单，系统支持**一揽子订单（Blanket Order）**、**分期交货**、**多供应商比价**等高级功能。"公司"（Companies）和"公司主数据"（Company Master）应用维护供应商信息，支持供应商评估和分类管理  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**采购合同与租赁/租赁合同管理**方面，Manage模块提供专门的合同管理应用套件，包括"采购合同"（Purchase Contracts）、"租赁/租赁合同"（Lease/Rental Contracts）、"人工费率合同"（Labor Rate Contracts）、"主合同"（Master Contracts）、"保修合同"（Warranty Contracts）以及"条款和条件"（Terms and Conditions） [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这些应用支持复杂的商业条款管理，如价格折扣、交货条件、质量保证、违约责任等。特别值得注意的是**"保修合同"**应用，该应用用于为外部服务提供商维护一个或多个资产，收取固定费用或定期付款；或按时间或计量器跟踪多个资产或位置的保修信息  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ，这一功能对于管理设备原厂保修和延保服务、避免重复维修支出具有重要价值。

#### 1.2.4 计划与调度（Planning & Scheduling）

计划与调度功能域代表了Maximo Manage在**资源优化方面**的核心能力，其产品描述中该领域的应用数量之多、功能之丰富，体现了IBM在企业级调度算法方面的深厚积累。

**作业计划（Job Plans）标准化管理**通过"作业计划"（Job Plans）应用实现，定义维护任务的标准工序、所需资源（人工、物料、工具）、安全要求等信息。作业计划支持**多级嵌套**，复杂维护任务可分解为多个子任务，每个子任务关联独立的作业计划。这种标准化设计确保了维护质量的一致性，简化了工单创建过程，并为能力计划和成本估算提供基础数据。

**路线（Routes）规划与优化**通过"路线"（Routes）应用实现，将多个按特定顺序执行的维护任务组合为优化路径。路线常用于巡检、润滑、清洁等需要按固定顺序访问多个资产的场景，系统支持基于地理位置或逻辑顺序的优化排序，减少移动时间，提升工作效率。

**资源水平管理与能力平衡**通过"资源水平管理"（Resource Levels Management）应用实现，帮助计划人员了解各时段的资源供需状况，识别瓶颈并进行能力调整。

**图形化调度功能套件**是Manage模块的显著特色，MAS 8.11版本提供了多达**9个图形化应用**  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ：

| 应用名称 | 核心功能 | 典型应用场景 |
|:---|:---|:---|
| **图形化工作周（Graphical Work Week）** | 以周视图展示工作计划 | 短期工作负载概览 |
| **图形化调度（Graphical Scheduling）** | 交互式工单排程与资源分配 | 复杂项目的多资源协调 |
| **图形化调度-大型项目（Graphical Scheduling – Large Projects）** | 支持复杂项目的多层级调度 | 年度大修、装置停工检修 |
| **图形化任务分配（Graphical Assignment）** | 可视化的人员-任务匹配 | 日常派工优化 |
| **图形化任务分配-维修设施（Graphical Assignment – Repair Facilities）** | 针对维修车间的专用调度 | 机车车辆、航空发动机维修 |
| **图形化班组管理（Graphical Crew Management）** | 班组资源的可视化配置 | 固定班组的工作安排 |
| **图形化预约簿（Graphical Appointment Book）** | 客户服务预约的时间槽管理 | 现场服务、客户维修预约 |

这些图形化应用基于**先进的调度算法引擎**，支持约束条件（如技能要求、资质认证、工作时间、地理位置）下的自动优化。特别值得关注的是**与Maximo Optimizer的集成**，该优化引擎采用IBM ILOG CPLEX技术，能够求解大规模资源分配问题的最优解或近似最优解，考虑技能匹配、位置约束、时间窗口、优先级等多重因素  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**调度管理支持应用**方面，"调度数据管理器"（Scheduler Data Manager）用于在调度或分配工作之前验证调度或工作列表的数据  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ；"预约簿管理器"（Appointment Book Manager）用于创建和更新预约簿，供客户服务代表在安排客户预约时使用  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ；"配置天气警报"（Configure Weather Alerts）和"配置天气预报"（Configure Weather Forecast）应用则集成了外部天气数据服务，当工作记录因天气事件而面临风险时，在图形和地图视图中突出显示  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这些细节功能体现了Manage模块对现场服务场景的深度理解和专业支持。

#### 1.2.5 安全管理（Safety）

安全管理模块将**职业健康与安全（OHS）要求**嵌入维护工作流程，确保维护活动的安全合规执行，是Manage模块满足高风险行业需求的关键能力。

**危险源（Hazards）识别与管理**通过"危险源"（Hazards）应用实现，维护企业识别的各类危险源清单，包括物理危险（高温、高压、辐射）、化学危险（有毒物质、易燃物）、生物危险、人机工程学危险等类别。每个危险源关联相应的风险等级和典型控制措施。

**预防措施（Precautions）制定**通过"预防措施"（Precautions）应用实现，与危险源建立关联关系，形成"危险源-预防措施"的结构化知识库。预防措施定义了针对特定危险源的具体控制行动，如上锁/挂牌程序、个人防护装备要求、工作区域隔离等。

**上锁/挂牌（Lock Out / Tag Out, LOTO）程序**通过专门的LOTO应用实现，管理能量隔离程序的制定、审批、执行和解除。LOTO是防止能量意外释放导致人员伤害的关键控制措施，系统支持定义设备特定的LOTO计划，包括能量源识别（电气、机械、液压、气动等）、隔离点位置、隔离方法、验证步骤等。LOTO执行过程严格记录，确保能量隔离的有效性和可追溯性。

**安全计划（Safety Plans）编制与执行**通过"安全计划"（Safety Plans）应用实现，将危险源、预防措施、LOTO程序、个人防护装备要求等整合为完整的安全计划。安全计划可以关联到作业计划，在生成工单时自动带入，确保现场人员获得完整的安全指导。

**检查表单模板管理**通过"管理检查表单"（Manage Inspection Forms）应用实现，支持安全检查、设备点检等各类检查活动的标准化执行  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。检查表单支持多种字段类型，可以配置为强制完成项，未完成则阻止工单状态推进，形成安全管理的硬性控制。

#### 1.2.6 财务管理（Financials）

财务管理模块为资产管理决策提供**经济分析基础**，确保资产价值的准确核算和维护成本的合理控制。

**多币种与汇率管理**通过"货币代码"（Currency Codes）和"汇率"（Exchange Rates）应用实现，支持跨国企业的多币种业务处理。系统支持交易币种和本位币的分离，自动汇率转换，以及汇率波动对成本计算的影响处理  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**会计科目表（Chart of Accounts）**通过"总账账户"（GL Accounts）应用实现，用于建立总账账户字段，其定义等同于企业财务数据处理系统其余部分使用的定义，实现EAM与ERP系统的财务集成  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

**成本管理与预算监控**通过"成本管理"（Cost Management）和"预算监控"（Budget Monitoring）应用实现。"成本管理"应用生成项目成本信息，以跟踪完成项目所需的财务资源并更有效地管理预算  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ；"预算监控"应用允许创建预算记录以监控财务期间内的交易，监控预算成本有助于确保项目或活动在商定的预算内完成，并可以改善未来项目成本的估算  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。系统支持按成本类型（人工、物料、外协）、按资产类别、按时间段的多维度预算编制和执行跟踪。

**资产折旧与价值评估**支持多种折旧方法（直线法、余额递减法、年数总和法等），自动计算折旧费用和账面价值。资产重估、减值测试、处置损益计算等功能，确保资产价值的准确反映和合规处理。

### 1.3 系统管理与配置

#### 1.3.1 组织架构管理（Sets, Organizations, Sites）

Maximo Manage采用**三级组织架构模型**，适应复杂企业的组织建模需求：

| 层级 | 功能定位 | 典型应用场景 |
|:---|:---|:---|
| **集合（Sets）** | 跨组织共享主数据的框架 | 集团级物料主数据、供应商主数据统一 |
| **组织（Organizations）** | 独立的财务实体或运营单位 | 不同法人公司、不同会计准则 |
| **站点（Sites）** | 具体的运营位置或业务单元 | 工厂、矿区、区域分公司 |

"集"用于创建跨多个组织共享项目和公司（供应商）数据的框架  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ；"组织"用于设置要在Maximo中使用的组织和站点  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ；"站点"则代表具体的运营位置，是大多数业务数据的主要隔离层级。这种设计既保证了数据的一致性，又支持必要的隔离和控制，使单一Maximo实例能够支持从单一站点企业到全球化多组织集团的多样化需求。

#### 1.3.2 日历与工作时间配置

"日历"（Calendars）应用用于指示设备、工种和人工记录的工作时间，适用于组织及其关联站点  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。系统支持多种日历类型：组织日历（定义工作日/休息日/节假日）、设备日历（特定资产的可用时间）、人员日历（个人班次和休假计划）。日历配置与调度引擎深度集成，是计划计算、SLA评估、成本计算的时间基础。

#### 1.3.3 资源主数据（人员、资质、工种、工作组）

资源管理应用套件涵盖维护活动的全部人力资源要素  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) ：

| 应用名称 | 功能描述 | 关键属性 |
|:---|:---|:---|
| **人工（Labor）** | 定义和维护人工记录 | 所属部门、成本中心、工作时间日历 |
| **资质（Qualifications）** | 创建资质和资质的认证要求 | 技能等级、有效期、再认证要求 |
| **人员（People）** | 维护人员记录 | 基本信息、联系方式、系统账号 |
| **人员组（Person Groups）** | 维护人员组 | 可能是或不是工作人员的人员集合 |
| **工种（Crafts）** | 定义和维护工种记录 | 标准费率、效率系数、关联资质 |
| **班组类型（Crew Types）** | 定义和维护班组的需求 | 工种构成、工具配备、能力标准 |
| **班组（Crews）** | 定义和维护班组记录及人工分配 | 固定成员、动态分配、工作区域 |

这种精细化的资源主数据设计，使调度系统能够基于**技能、资质、地理位置、成本**等多维度因素进行智能匹配。MAS 8.11版本引入的"图形化班组管理"（Graphical Crew Management）应用，以可视化方式展示班组构成、技能组合、工作安排等，进一步提升了资源管理的直观性和效率  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。

#### 1.3.4 工作区域（Work Zones）与图形化班组管理

"工作区域"（Work Zones）应用用于将地理区域划分为更小的工作区域，减少工单之间的旅行时间，然后根据资源关联的工作区域将工作分配给资源  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这一功能对于优化现场服务团队的路线和响应时间具有重要价值，特别适用于地理分散的服务网络（如电力巡检、设备维保、设施管理）。

#### 1.3.5 分类体系（Classifications）与条件表达式管理

"分类"（Classifications）应用已在前文详细介绍。"条件表达式管理器"（Conditional Expression Manager）用于创建和维护条件库，在应用设计器和安全组等应用中，从预定义条件中进行选择以设置条件行为  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。这一功能支持复杂的业务规则配置，如：

#### 2.2.3 智能规则与告警引擎

Monitor的告警机制支持**从简单阈值到复杂AI的多层次规则配置**：

| 规则类型 | 技术原理 | 适用场景 | 配置复杂度 |
|:---|:---|:---|:---|
| **静态阈值** | 固定上下限值 | 边界明确的参数（如温度上限、压力下限） | 低 |

| **组合条件** | 多参数逻辑组合 | 复杂工况判断（如高温+低压同时出现） | 中高 |
| **AI异常检测** | 机器学习模型自动识别偏离 | 未知故障模式发现、早期微弱异常 | 低（预置）/高（自定义） |

### 2.3 AI驱动的异常检测

#### 2.3.1 基于机器学习的异常模式识别

Monitor集成了**IBM的AI能力**，提供先进的异常检测功能，其核心优势在于**超越简单阈值的多维度模式识别**：

- **多变量相关性分析**：识别单参数正常但组合异常的情况（如温度正常、压力正常，但温度-压力关系异常）
- **工况自适应**：自动学习不同运行模式下的正常基准，减少工况变化导致的误报
- **早期微弱信号发现**：捕捉人类难以察觉的渐进性退化迹象

机器学习异常检测的**典型应用场景**包括：旋转机械的轴承早期磨损（振动频谱微妙变化）、电气设备的绝缘老化（局部放电模式演变）、过程设备的效率衰减（多参数协同退化）等。

#### 2.3.2 无监督学习异常检测

对于**缺乏充足故障样本**的场景，Monitor支持多种无监督学习方法：

| 算法类型 | 核心思想 | 适用数据特征 |
|:---|:---|:---|
| **统计方法** | 3-sigma、IQR等基于分布假设 | 单变量、近似正态分布 |
| **聚类方法** | DBSCAN、K-means识别离群点 | 多变量、存在自然分组 |
| **密度方法** | 局部异常因子（LOF） | 不同区域密度差异大 |
| **重构方法** | 自编码器（Autoencoder） | 高维、非线性关系 |
| **预测方法** | LSTM时间序列预测 | 强时序相关性 |

无监督方法的**核心优势**在于无需标注的故障数据即可开始应用，特别适合新投运设备或故障 rare 的关键设备。企业可以从无监督检测开始积累异常案例，逐步过渡到监督学习以提高准确性。

#### 2.3.3 异常根因分析与推荐

高级版本的Monitor集成**根因分析能力**，当检测到异常时：

1. **关联分析**：识别与异常同时发生的其他事件或参数变化
2. **贡献度排序**：量化各相关因素对异常的贡献程度
3. **知识库匹配**：将异常特征与历史案例、FMEA库进行比对
4. **修复建议**：基于匹配结果推荐经过验证的检查步骤和修复措施

这种**"检测-诊断-建议"的完整链条**，将监控从单纯的状态展示提升为智能决策支持，显著缩短故障诊断时间，提升首次修复率。

### 2.4 数据管理与分析

#### 2.4.1 时序数据存储与压缩

| 技术策略 | 具体方法 | 效果 |

#### 2.4.2 数据质量管理与清洗

原始传感器数据普遍存在质量问题，Monitor提供**全链路数据质量管理**：

| 质量问题 | 检测方法 | 处理策略 |
|:---|:---|:---|
| **数据缺失** | 时间戳连续性检查 | 插值填充（线性/前向/基于模型）或标记 |
| **异常值** | 物理范围检查、统计离群检测 | 标记、修正或删除 |
| **数据漂移** | 长期趋势分析、基线比较 | 提示传感器校准需求 |
| **时间戳错乱** | 顺序检查、时钟同步验证 | 重新排序或标记 |
| **噪声干扰** | 变化率分析、频谱分析 | 移动平均、卡尔曼滤波等平滑处理 |

数据质量评分和报告帮助用户持续监控数据健康度，识别需要维护或校准的传感器。

#### 2.4.3 监控数据与资产主数据关联

Monitor通过**资产数据字典（Asset Data Dictionary, ADD）**机制，确保每个数据点都与正确的资产身份关联。这种关联支持：

- **双向导航**：从资产台账查看其所有监控点和实时状态，从监控数据追溯到资产属性、维护历史、相关文档
- **多维度聚合**：按资产类型、位置、责任部门、制造商等维度进行数据汇总和对比分析
- **上下文增强**：将原始数值转化为有意义的业务信息（如"当前振动值超过该型号历史平均的2个标准差"）

## 3. Maximo Health（资产健康管理）

### 3.1 平台定位与核心价值

#### 3.1.1 资产健康状态的综合评估平台

**Maximo Health**是IBM Maximo Application Suite中专注于**资产健康评估和风险管理**的核心应用，与Monitor、Predict共同构成完整的资产绩效管理（APM）能力  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。Health的核心使命是将分散的资产数据整合为**统一的健康视图**，回答资产管理中最关键的问题：**"资产当前状态如何？"**

与Monitor专注于实时数据监控不同，Health更强调**历史数据的综合分析和长期趋势评估**，是连接实时监控与预测性维护的桥梁。Health的设计哲学是**"一种维护策略不适合所有资产"**——对于关键资产需要积极的维护策略以避免非计划停机，对于非关键资产运行至故障（Run-to-Failure）可能是更经济的选择  [(sms-inc.net)](https://www.sms-inc.net/hubfs/IBM%20Maximo%20Health.pdf?hsLang=en) 。通过多维度的健康评估，Health帮助企业为不同资产制定差异化的维护策略，实现维护资源的精准投放。

Health的典型用户是**可靠性工程师（Reliability Engineer）**，其职责是确保关键资产系统的可靠运行，并基于数据做出维护和投资决策  [(IBM on GitHub)](https://ibm.github.io/maximo-labs/apm_9.0/demo_script/) 。Health提供的健康评分和风险分析工具，帮助可靠性工程师从海量数据中提炼洞察，识别最需要关注的资产，优化维护资源配置。

#### 3.1.2 风险导向的维护策略优化

Health将**风险管理理念**系统性地引入维护决策，其核心框架是**风险 = 故障概率 × 业务影响**。传统维护策略往往基于固定周期或简单阈值，未能充分考虑资产的个体差异和动态变化。Health通过量化评估：

| 评估维度 | 关键输入 | 评估方法 |
|:---|:---|:---|
| **故障概率** | 健康评分、年龄、历史故障率、运行工况 | 统计模型、机器学习预测 |
| **业务影响** | 资产关键性、生产依赖性、安全环境影响、更换成本 | 结构化评分、专家评估 |

基于风险计算，Health生成**风险矩阵**可视化展示，直观识别"高概率高影响"的高风险资产，优先分配维护资源。这种方法确保**有限的维护预算产生最大的风险降低效果**，实现风险调整后的最优回报。

#### 3.1.3 财务优化的维护决策支持

Health将**财务维度**纳入维护决策，支持维护策略的经济性评估和优化。MAS 8.11版本强化了**资产投资优化器（Asset Investment Optimizer）**功能，该功能允许企业：

1. **构建多年期资产更换项目**：添加候选资产、设定预算约束、定义风险容忍度
2. **运行多种场景模拟**：比较"立即更换"、"延期维修"、"继续运行"等策略
3. **确定最优更换时机和优先级**：基于NPV、IRR、风险降低效益等指标

这种**技术与财务的整合**，使资产管理决策能够与企业的资本规划、预算管理流程对接，提升了资产管理在组织战略决策中的话语权  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2024/03/07-PACMUGC24_MAS_Update_IBM.pdf) 。

### 3.2 健康评估体系

#### 3.2.1 多维度健康评分模型

**资产健康评分（Health Score）**是Health模块的核心输出，通常为0-100的归一化数值，综合反映资产的整体健康状态。

**评分计算机制**基于可配置的评分模型，整合多种输入因素：

| 因素类别 | 具体指标 | 数据来源 | 典型权重 |
|:---|:---|:---|:---|
| **状态监测数据** | 振动、温度、压力、电流等实时参数偏离度 | Maximo Monitor | 20-40% |
| **检测分析数据** | 油液分析、红外检测、超声波检测等离线检测 | Maximo Mobile/Manage | 15-25% |
| **维护历史** | 近期故障频率、维修次数、维修成本趋势 | Maximo Manage | 15-25% |
| **使用强度** | 运行小时、循环次数、负荷率、启停次数 | 计量表读数 | 10-20% |
| **年龄因素** | 役龄、有效年龄、设计寿命消耗比例 | 资产主数据 | 10-15% |
| **环境因素** | 腐蚀环境、温度极端性、污染程度 | 位置属性/外部数据 | 5-10% |

**自定义评分规则与权重配置**是Health的灵活之处。系统提供评分组（Score Groups）和评分类型（Score Types）机制，允许为不同资产类别定义专门的评分模型。IBM官方实验室指南展示了如何为**变电站变压器**创建自定义评分方法，包括定义效率评分组和构建自定义评分矩阵  [(IBM on GitHub)](https://ibm.github.io/maximo-labs/apm_9.0/build_demo/) 。企业可以根据自身经验和数据特点，调整各因素的权重、定义评分曲线（线性、阶梯、自定义函数）、设置评分范围映射。

**评分趋势分析与历史追踪**支持健康状态的动态监控。系统保存每次评分计算的结果，形成健康历史曲线，支持：
- **趋势识别**：健康评分加速下降提示需要关注
- **对比分析**：同类资产的健康基准建立，识别表现异常的个股
- **效果评估**：维护干预前后的健康变化量化

#### 3.2.2 风险分析与管理

**资产风险等级评估**将健康评分与资产关键性相结合。关键性评估通常基于多维度结构化评分：

| 关键性维度 | 评估内容 | 典型权重 |
|:---|:---|:---|
| **安全影响** | 故障导致的人员伤害、环境破坏风险 | 25-35% |
| **生产影响** | 故障导致的产量损失、交付延误 | 25-35% |
| **质量影响** | 故障导致的产品质量问题、客户投诉 | 15-25% |
| **成本影响** | 故障的直接维修成本、间接损失 | 15-25% |
| **替代可用性** | 备用设备、替代工艺的可获得性 | 10-15% |

**风险矩阵与可视化**是Health的标志性功能。MAS 8.11版本强化了矩阵的交互能力，支持：

| 矩阵维度组合 | 应用场景 | 可视化特征 |
|:---|:---|:---|
| 关键性-风险（Criticality-Risk） | 识别高风险关键资产 | 颜色编码（绿-黄-橙-红） |
| 关键性-健康（Criticality-Health） | 发现健康不佳的关键资产 | 气泡大小表示资产价值 |
| 关键性-寿命终结（Criticality-End of Life） | 规划更换优先级 | 未来日期预测展示 |

用户可**自定义矩阵维度、分级阈值、颜色方案**，创建符合自身管理需求的分析视图。钻取功能支持从矩阵单元格直接查看该风险区间的资产清单，以及预测未来日期的矩阵状态  [(Total Resource Management)](https://trmgroup.com/resource/what-is-new-in-mas-8-11/) 。

**风险驱动的工作优先级排序**将风险分析结果直接转化为行动计划。系统可以自动生成基于风险的工作建议，或调整现有工单的优先级，确保高风险资产获得及时响应。

#### 3.2.3 关键性分析（Criticality Analysis）

**资产关键性评级**是风险评估的基础输入。Health支持结构化的关键性评估流程，通常采用**多准则决策方法**（如AHP层次分析法），确保评估的客观性和一致性。

**业务影响评估**深入分析资产故障的具体后果。对于关键资产，可以建立详细的影响模型：
- **故障模式分析**：哪些方式可能故障，每种模式的概率和后果
- **故障检测时间**：多久能发现问题（依赖于监控覆盖度）
- **故障响应时间**：多久能恢复运行（依赖于备件可用性、人员技能）
- **故障恢复成本**：直接维修费用和间接损失（生产损失、违约金、声誉损害）

**关键性驱动的资源分配**确保关键资产获得充分保障：
- **监控强度**：关键资产配置更多传感器、更高采集频率
- **备件策略**：关键资产保持更高安全库存、更近存储位置
- **维护标准**：关键资产采用更严格的预防性维护、更短维护间隔
- **响应机制**：关键资产故障触发更快速的响应流程、更高层级介入

### 3.3 数据融合与分析

#### 3.3.1 多源数据整合

Health的数据整合能力是其区别于单一数据源分析工具的关键优势，形成**资产的360度视图**：

| 数据源            | 数据类型              | 整合方式       | 应用场景        |
| :------------- | :---------------- | :--------- | :---------- |
| Maximo Manage  | 资产主数据、台账信息、技术规格   | 直接数据库集成    | 资产身份、基础属性   |
| Maximo Manage  | 工单历史、维护记录、成本数据    | 数据库查询/API  | 维护强度、维修效果评估 |
| Maximo Manage  | 故障记录、失效模式、故障代码    | 事件触发更新     | 故障频率统计、模式识别 |
| Maximo Monitor | IoT传感器实时数据、异常事件   | ADD同步/流式接入 | 实时状态、趋势分析   |
| Maximo Mobile  | 检查结果、检测数据、现场观察    | 批量同步/实时上传  | 离线检测、人工评估   |
| 外部系统           | ERP成本数据、生产数据、环境数据 | ETL/API集成  | 财务分析、工况关联   |

这种多源整合通过Maximo Application Suite**统一的数据模型和集成框架**实现，避免了传统数据仓库项目中复杂的ETL开发和数据延迟问题。产品描述特别强调，Health的价值在于"将IT数据（来自Manage）和OT数据（来自Monitor）混合显示在单一视图中"  [(IBM on GitHub)](https://ibm.github.io/maximo-labs/apm_9.0/demo_script/) 。

#### 3.3.2 健康洞察生成

基于整合的多源数据，Health生成丰富的**可操作的洞察**：

**资产健康状态可视化**通过多层次展示满足不同角色需求：
- **高管仪表盘**：关键指标汇总（平均健康评分、高风险资产数量、健康趋势）
- **可靠性工程师视图**：详细评分构成、影响因素贡献度、预测模型性能
- **现场主管视图**：负责区域的健康分布、待处理预警、工作计划

**健康下降预警**主动识别需要关注的资产。预警触发条件包括：
- 健康评分绝对值跌破阈值（如低于60分）
- 健康评分相对下降超过比例（如一周内下降10%）
- 健康评分变化率加速（下降速度加快）

**维护建议自动生成**基于健康评估结果和预设规则，推荐具体行动：
| 健康状态 | 典型建议 | 紧急程度 |
|:---|:---|:---|
| 优秀（>80分） | 继续当前维护策略，可适当延长间隔 | 低 |
| 良好（60-80分） | 加强监控，安排下次计划停机时检查 | 中 |
| 一般（40-60分） | 尽快安排详细检查，准备维修方案 | 高 |
| 较差（<40分） | 立即安排检查，考虑降负荷运行或更换 | 紧急 |

### 3.4 自定义仪表盘与报告

#### 3.4.1 角色化健康视图

Health支持为不同角色定制信息视图，确保各层级用户获得最相关的信息：

| 角色 | 核心关注 | 典型视图内容 |
|:---|:---|:---|
| **资产经理** | 资产组合整体表现 | 健康分布统计、风险热力图、KPI趋势、更换投资计划 |
| **可靠性工程师** | 技术分析和模型优化 | 评分模型详情、预测准确性、影响因素分析、改进建议 |
| **维护计划员** | 工作执行和资源安排 | 待处理预警、建议维护任务、资源需求、时间安排 |
| **现场技术人员** | 负责资产的健康状态 | 资产健康卡片、待完成检查、历史维护记录、技术文档 |
| **财务规划人员** | 投资优化和成本控制 | 更换场景对比、NPV分析、预算执行、成本趋势 |

#### 3.4.2 自定义健康指标与仪表

除预置的健康评分外，Health允许用户定义**自定义指标**满足特定分析需求：

- **专项健康指数**：如"泵类设备健康指数"、"生产线A综合健康评分"
- **复合业务指标**：如"维护成本效率"（单位产出的维护成本）、"合规状态"（检测完成率、证书有效性）
- **预测性指标**：如"预期故障时间窗口"、"剩余经济寿命"

自定义指标支持基于Maximo公式语言或Python脚本的复杂计算，可以纳入仪表盘监控和报告生成。

#### 3.4.3 健康报告自动生成与分发

Health支持**报告的自动化生成和多渠道分发**：

| 报告类型 | 生成频率 | 主要内容 | 分发对象 |
|:---|:---|:---|:---|
| 健康摘要报告 | 每日/每周 | 关键指标概览、异常资产清单、趋势变化 | 管理层、可靠性工程师 |
| 风险分析报告 | 每月/每季度 | 风险矩阵演变、高风险资产深度分析、改进建议 | 资产经理、安全主管 |
| 更换规划报告 | 每半年/每年 | 更换候选资产、场景对比分析、投资建议 | 财务规划、高管层 |
| 合规审计报告 | 按需 | 检测完成率、证书状态、审计追踪 | 质量合规、外部审计 |

报告支持PDF、Excel、HTML等多种格式，可通过邮件自动分发或发布到共享门户。

## 4. Maximo Predict（预测性维护与AI分析）

### 4.1 平台定位与技术基础

#### 4.1.1 基于AI/ML的预测性维护引擎

**Maximo Predict**是IBM Maximo Application Suite中专注于**预测性分析的高级应用**，代表资产管理从"状态感知"向"未来预测"的能力跃升。根据IBM官方描述，Predict的核心价值在于"超越基于时间的维护，实现基于状态的行动，通过应用机器学习和数据分析预测未来故障的可能性，从而降低成本和资产故障"  [(Avenue)](https://avenue-net.com/wp-content/uploads/2022/10/Maximo-Application-Suite-solution-brief-read-more.pdf) 。

Predict的技术基础是**IBM Watson机器学习平台**，包括：
- **Watson Studio**：交互式模型开发环境，支持Jupyter Notebook
- **Watson Machine Learning**：模型训练、部署和推理服务
- **Cloud Pak for Data**：企业级数据科学平台，作为MAS的组成部分提供  [(IBM on GitHub)](https://ibm.github.io/maximo-labs/apm_9.0/demo_script/) 

这种架构确保了**企业级AI能力的可扩展性、安全性和治理合规性**，同时通过预置模型和自动化工作流降低使用门槛，使缺乏专业数据科学团队的组织也能部署和受益于预测性维护。

#### 4.1.2 Maximo Health的能力延伸与增强

Predict与Health存在**紧密的能力递进关系**。需要特别澄清的是：在MAS的产品架构中，**Predict是Health的能力增强版本，包含Health的全部功能，并增加了专有的预测模型和高级分析功能**  [(Total Resource Management)](https://trmgroup.com/resource/what-is-new-in-mas-8-11/) 。这种设计避免了功能重复，同时为不同成熟度的客户提供了渐进式的采用路径：

| 采用阶段 | 核心模块 | 核心能力 | 典型用户 |
|:---|:---|:---|:---|
| 第一阶段 | Maximo Health | 健康评分、风险矩阵、维护建议 | 刚开始数据驱动维护的企业 |
| 第二阶段 | Maximo Predict（含Health） | 故障预测、RUL估计、场景优化 | 具备数据基础、追求预测性维护的企业 |

具体而言，Health提供**当前健康状态的评估**和基于历史趋势的外推，Predict则引入**机器学习模型实现更深度的模式识别和未来预测**。Health的健康评分可以作为Predict模型的输入特征，Predict的预测结果（故障概率、RUL）又可以丰富Health的风险评估维度，形成相互增强的闭环。

#### 4.1.3 面向可靠性工程师的专业工具

Predict的设计充分考虑了**可靠性工程师（Reliability Engineer）**的专业需求，同时兼顾**数据科学家**的自定义开发需求：

| 用户角色 | 核心需求 | Predict支持能力 |
|:---|:---|:---|

### 4.2 核心预测能力

#### 4.2.1 故障预测模型

Predict提供**多种类型的故障预测输出**，满足不同决策场景的需求：

| 预测类型 | 输出形式 | 核心算法 | 应用场景 |
|:---|:---|:---|:---|
| **故障概率预测（Failure Probability）** | 未来特定时间段内的故障概率（0-100%） | 生存分析、梯度提升、神经网络 | 风险优先级排序、维护计划调整 |
| **预期故障日期预测** | 最可能的故障时间窗口（如"15-20天内"） | 时间序列预测、退化轨迹外推 | 精确维护调度、备件准备、生产协调 |
| **故障模式识别与分类** | 最可能的故障类型（如"轴承磨损"） | 多分类模型、模式匹配 | 针对性维护准备、专用工具备件、技能安排 |

**故障概率预测**是Predict的基础输出，其计算综合考虑：
- 历史故障模式（同类设备的故障历史）
- 当前状态指标（传感器实时数据、健康评分）
- 运行工况（负荷、环境、操作模式）
- 维护历史（维护频率、维护类型、维护效果）

与简单的"正常/异常"判断相比，**概率化表达更符合工程实际**——确定性预测往往难以实现，而概率评估支持风险决策和不确定性管理。

**预期故障日期预测**对于维护计划编制具有直接指导价值。系统估算故障最可能发生的时间点，通常以**概率分布形式**呈现（如中位数预测、置信区间），帮助确定"最佳维护窗口"——既避免过早维护的资源浪费，又避免过晚维护的故障风险。

**故障模式识别**指导维护准备的针对性。当系统预测"轴承磨损"为最可能的故障模式时，维护团队可以提前准备振动分析工具、轴承备件、以及具备轴承更换技能的人员，显著提升维护效率。

#### 4.2.2 剩余使用寿命预测（RUL - Remaining Useful Life）

**RUL预测是Predict的核心差异化能力**，估算资产从当前状态到功能失效的剩余时间。RUL估算的技术路径包括：

| 方法类型 | 技术原理 | 数据需求 | 适用场景 |
|:---|:---|:---|:---|
| **基于物理的模型** | 失效物理知识（疲劳裂纹扩展、磨损累积） | 材料参数、设计规格、运行条件 | 机理明确的退化过程（如轴承、齿轮） |
| **数据驱动的模型** | 历史退化数据训练机器学习模型 | 同类设备的完整寿命历史 | 机理复杂或未知的退化过程 |
| **混合模型** | 物理模型约束+数据驱动参数估计 | 部分物理知识+部分历史数据 | 兼顾可解释性和适应性 |

**多因素RUL调整**考虑影响寿命的多种因素：
- **运行工况**：高负荷、频繁启停加速退化
- **维护历史**：及时维护延长寿命，不当维护缩短寿命
- **环境因素**：腐蚀、高温、污染加速老化
- **个体差异**：同型号设备因制造差异、安装质量导致的寿命差异

**RUL趋势可视化**展示RUL估计的历史变化和置信区间，支持：
- **退化速度识别**：RUL消耗加速提示需要关注
- **维护效果评估**：维护后RUL延长验证维护有效性
- **更换时机优化**：结合生产计划、预算周期确定最优更换窗口

#### 4.2.3 关键性能指标预测

除故障预测外，Predict支持**关键性能指标（KPI）的趋势预测**：

| KPI类型 | 预测内容 | 应用场景 |
|:---|:---|:---|
| **性能退化趋势** | 效率、精度、产能等指标的 future evolution | 产能规划、质量预控、能效优化 |
| **关键参数超限预警** | 过程参数何时超出安全/质量限值 | 前瞻性运行调整、避免质量事故 |
| **维护窗口优化建议** | 综合考虑RUL、生产计划、资源可用性的最优时机 | 平衡可靠性和生产效率 |

|:---|:---|:---|:---|

**再训练流程**可以配置为自动执行或人工审批后执行，利用最新的数据更新模型参数，适应设备老化、工况变化等带来的分布漂移。

Predict支持**企业级AI治理**所需的模型管理能力：

- **影子模式**：新模型与生产模型并行运行，仅记录预测不实际使用，验证后再切换

### 4.4 预测结果应用

#### 4.4.1 预测驱动的维护计划生成

Predict的预测结果**直接驱动维护计划的动态调整**：

| 预测输出 | 维护行动 | 计划系统响应 |
|:---|:---|:---|
| 故障概率 > 阈值（如30%） | 安排详细检查或预防性维护 | 自动生成工单，纳入调度系统 |
| RUL < 计划提前期 | 启动更换或大修准备 | 创建项目工单，协调资源 |
| 故障模式明确 | 准备针对性维护方案 | 工单携带建议措施、备件、工具 |
| 性能将超限 | 调整运行参数或安排停机 | 通知操作人员，建议运行调整 |

这种"由数据驱动"的计划补充了传统的基于时间或基于运行的计划，实现了**更精准的维护时机选择**。典型效果包括：延长健康状态良好资产的维护间隔（节省成本）、提前退化加速资产的维护执行（降低风险）。

#### 4.4.2 预测结果与工单系统集成

预测结果与Maximo Manage的工单系统**深度集成**：

- **工单创建**：预测触发自动创建工单，携带完整上下文
- **工单内容**：预测置信度、建议故障模式、建议维护措施、关联备件工具
- **工单优先级**：基于故障概率和影响自动计算优先级
- **工单跟踪**：维护结果反馈用于模型性能评估和改进

维护人员在执行工单时可以查看预测信息，辅助其诊断和维修决策。例如，当系统提示"基于振动趋势分析，该轴承预计在未来2周内失效"时，技术人员可以有针对性地进行振动检测验证，提高诊断效率。

#### 4.4.3 备件需求预测与库存优化

基于RUL预测和设备清单，系统可以**预测未来一段时间内的备件需求**：

| 优化维度 | 传统方法 | 预测驱动方法 |
|:---|:---|:---|
| **高价值长周期备件** | 固定安全库存 | 基于RUL分布动态调整，提前采购 |
| **通用 consumable** | 经济订货批量 | 聚合预测需求，优化订货时机 |
| **关键备件** | 最高库存水平 | 基于风险容忍度精确配置 |

这种优化显著降低了**缺货导致的停机风险**和**过量库存的资金占用**，典型改进包括：库存周转率提升20-30%，紧急采购减少40-50%。

#### 4.4.4 维护资源优化配置

预测性维护使维护需求**更加可预见**，支持资源的战略性配置：

| 资源配置维度 | 优化策略 | 典型效果 |

| **工具设备** | 预测性准备专用检测和维修工具 | 减少等待时间，提升维修效率 |
| **外包服务** | 提前预约关键外包资源 | 避免紧急外包的高成本 |

### 4.5 可靠性分析工具

#### 4.5.1 威布尔分析（Weibull Analysis）

**威布尔分析**是可靠性工程的经典方法，Predict将其集成用于故障数据分析和可靠性参数估计：

| 分析内容 | 输出结果 | 应用场景 |
|:---|:---|:---|
| 威布尔参数估计 | 形状参数β（失效模式）、尺度参数η（特征寿命） | 识别失效类型（早期失效、随机失效、磨损失效） |
| 可靠性函数 | R(t) = 可靠度随时间变化 | 保修期设计、更换时机优化 |
| 失效率函数 | λ(t) = 瞬时失效率 | 维护策略选择（年龄更换、块更换） |
| 平均剩余寿命 | MTBF、MTTF、MTTR | 备件库存计算、维护资源规划 |

Predict支持从Manage的故障历史数据**自动提取分析数据集**，进行参数估计和假设检验，生成可视化报告。

#### 4.5.2 可靠性增长分析

对于**新设备或经过设计改进的设备**，可靠性增长分析跟踪故障率随时间的变化趋势：

| 分析模型 | 适用场景 | 关键输出 |
|:---|:---|:---|
| **Duane模型** | 早期开发阶段 | 累积MTBF、增长速率 |
| **Crow-AMSAA模型** | 成熟期产品改进 | 强度函数、预期故障数 |

分析结果用于**评估可靠性改进措施的效果**，支持目标设定和资源分配决策。

#### 4.5.3 失效模式与影响分析（FMEA）支持

Predict的数据分析能力**支持FMEA的持续更新和优化**：

| FMEA要素 | Predict支持 | 价值 |
|:---|:---|:---|
| 失效模式识别 | 历史故障数据挖掘、预测模型输出 | 发现实际高频失效模式 |
| 发生度（O）评分 | 故障频率统计、故障概率预测 | 客观量化而非主观估计 |
| 探测度（D）评分 | 监控覆盖度分析、预测模型性能 | 评估现有监控和预测能力 |
| 改进措施效果 | 维护后故障率变化、RUL延长 | 验证改进措施的有效性 |

这种**数据驱动的FMEA更新**，使风险管理从静态文档转变为动态优化的过程。

| **实时同步** | 在线模式下操作即时同步 | 管理人员及时掌握现场状态 |
| **延迟同步** | 离线模式下本地存储，网络恢复后自动上传 | 支持无网络环境持续作业 |
| **权限体系** | 继承Manage的安全组和角色 | 统一的身份和访问管理 |

这种深度集成确保了**现场与后台的数据一致性和流程连贯性**，现场作业人员在Mobile应用中的操作实时反映到Manage系统，管理人员的调度指令即时推送到Mobile应用。

### 5.2 核心移动能力

#### 5.2.1 离线/在线混合模式

**离线能力是Mobile的核心技术优势**，这对工业现场环境至关重要——许多作业地点网络覆盖不稳定或完全无网络（如地下设施、偏远站点、海上平台）。

| 模式 | 数据机制 | 适用场景 |
|:---|:---|:---|
| **在线模式** | 实时连接Manage服务器，数据即时同步 | 网络良好的室内环境、办公室 |
| **离线模式** | 本地数据库存储，操作延迟同步 | 网络不稳定或无网络环境 |
| **混合模式** | 智能切换，优先本地操作，后台同步 | 大多数现场作业场景 |

**离线数据缓存与本地存储**的具体机制：
- **预下载策略**：网络可用时自动下载分配工单、相关资产信息、作业指导、物料主数据等
- **本地数据库**：SQLite存储，支持复杂查询和事务处理
- **操作队列**：离线期间的所有操作（数据录入、状态更新、时间记录）按顺序存储
- **附件管理**：照片、视频等大文件本地存储，压缩后批量上传

**网络恢复后的自动同步**流程：
1. 检测网络可用性，建立安全连接
2. 上传离线期间的操作队列，按时间顺序执行
3. 下载服务器端的更新（如工单重新分配、计划变更）
4. 同步完成后更新本地数据状态

**冲突检测与解决机制**处理离线期间的并发修改：
| 冲突场景 | 检测方法 | 解决策略 |
|:---|:---|:---|
| 同一工单被多人修改 | 时间戳比较、版本号检查 | 最后写入优先、服务器优先、或人工合并 |
| 工单被重新分配 | 分配状态校验 | 提示当前用户，建议释放或确认 |
| 计划已变更 | 计划版本比对 | 显示变更内容，建议调整或继续 |

#### 5.2.2 角色化移动应用

Mobile平台采用**"一个应用，多种角色"**的设计理念，单一Mobile应用框架支持为不同角色配置差异化的功能界面：

## 6. 模块协同与集成架构

### 6.1 数据流与信息共享

#### 6.1.1 统一资产主数据模型

Maximo Application Suite的五大模块共享**统一的资产主数据模型**，这是模块协同的基石。Manage模块作为资产主数据的权威来源，为其他模块提供一致的资产标识、分类、属性信息：

| 数据实体 | 管理模块 | 消费模块 | 同步机制 |
|:---|:---|:---|:---|
| **资产主数据** | Manage | Monitor, Health, Predict, Mobile | 实时API/数据库复制 |
| **位置层次** | Manage | 全部模块 | 统一查询服务 |
| **分类属性** | Manage | 全部模块 | 缓存+增量更新 |
| **工单数据** | Manage | Health, Predict, Mobile | 实时事件流 |
| **计量表读数** | Manage（来自Monitor） | Health, Predict | 流式接入 |

这种统一模型避免了数据冗余和不一致，确保跨模块的分析和决策基于**同一事实基础**。

#### 6.1.2 跨模块工作流联动

产品描述强调了"共享数据和工作流"的用户体验优势  [(pacmug.org)](https://pacmug.org/wp-content/uploads/2025/05/MASTALK06PacMUGC25_MAS_ProductDecriptionGuideR8.11_IBM.pdf) 。典型的跨模块工作流联动场景：

| 触发模块 | 触发事件 | 响应模块 | 响应动作 | 业务价值 |
|:---|:---|:---|:---|:---|
| **Monitor** | 检测到异常（AI或阈值） | Manage | 自动创建服务请求或工单 | 从发现到响应的分钟级闭环 |
| **Health** | 健康评分显著下降 | Predict | 启动RUL预测分析 | 深度分析退化原因和速度 |
| **Predict** | 故障概率超过阈值 | Manage | 生成预防性维护工单 | 在故障发生前主动干预 |
| **Mobile** | 现场发现重大缺陷 | Manage/Health | 更新资产状态、触发健康重新评估 | 现场洞察即时纳入分析 |
| **Manage** | 维护完成反馈 | Health/Predict | 更新健康评分、验证预测准确性 | 持续改进模型性能 |

#### 6.1.3 实时数据与历史数据融合

Monitor提供的**实时时序数据**与Manage积累的**历史事务数据**，在Health和Predict模块中融合分析：

| 数据类型 | 时间特征 | 分析价值 | 融合应用 |
|:---|:---|:---|:---|
| **实时传感器数据** | 秒级-分钟级 | 当前状态感知、异常即时检测 | 健康评分实时更新、告警触发 |
| **短期历史数据** | 小时-天-周 | 趋势识别、模式发现 | 健康趋势分析、退化检测 |
| **长期历史数据** | 月-年-全生命周期 | 可靠性建模、寿命预测 | 威布尔分析、RUL预测、投资优化 |
| **事务记录数据** | 事件驱动 | 维护效果评估、成本分析 | 维护策略优化、ROI计算 |

这种**多时间尺度的数据融合**，使分析模型既能捕捉当前的运行状态，又能利用长期的历史模式，提高预测的准确性和鲁棒性。

### 6.2 典型业务场景集成

#### 6.2.1 监控-健康-预测-维护的闭环流程

这是Maximo Application Suite的**核心价值场景**，形成完整的资产绩效管理闭环：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Monitor   │───→│    Health   │───→│   Predict   │───→│   Manage/   │
│  实时数据采集 │    │  健康综合评估 │    │  故障预测   │    │   Mobile    │
│  异常即时检测 │    │  风险优先级  │    │  维护优化   │    │  维护执行   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       ↑                                                    │
       └──────────────── 反馈：维护结果、新运行数据 ←────────┘
```

**流程详解**：
1. **Monitor**持续采集设备运行数据，AI异常检测识别潜在问题
2. **Health**综合多源数据评估资产健康，识别需要关注的资产
3. **Predict**对高风险资产进行深度分析，预测故障时间和模式
4. **Manage/Mobile**基于预测结果制定维护计划，执行现场作业
5. **反馈**：维护结果和新的运行数据回流，持续优化模型

#### 6.2.2 移动现场作业与后台管理的协同

| 协同场景 | 后台（Manage） | 现场（Mobile） | 协同机制 |
|:---|:---|:---|:---|
| **任务分派** | 调度员在图形化界面分配工单 | 技术人员实时接收推送通知 | 实时同步+离线缓存 |
| **进度跟踪** | 管理人员监控工单状态和位置 | 技术人员更新进度和备注 | GPS定位+状态更新 |
| **专家支持** | 可靠性工程师分析复杂问题 | 现场人员视频连线请求协助 | 集成视频通话、AR标注 |
| **质量验收** | 质检员审核完成照片和记录 | 技术人员提交完工证据 | 电子签名+照片上传 |
| **知识沉淀** | 故障解决方案入库 | 现场经验即时记录 | 结构化模板+语音输入 |

#### 6.2.3 预测性维护与计划调度的联动

| 预测输出 | 调度优化 | 资源配置 | 效果度量 |
|:---|:---|:---|:---|
| RUL分布 | 优化维护窗口，平衡生产计划 | 提前协调停机窗口、备件到货 | 计划达成率、生产损失 |
| 故障概率排序 | 动态调整工单优先级 | 高技能人员优先配置高风险任务 | 首次修复率、返修率 |
| 故障模式预测 | 准备针对性维护方案 | 专用工具、特定备件、专家待命 | 维修时间、备件命中率 |
| 群体预测 | 聚合需求，优化资源池 | 人员培训、外包预约、库存策略 | 资源利用率、成本控制 |

### 6.3 技术平台统一性

#### 6.3.1 共享的Red Hat OpenShift容器平台

Maximo Application Suite全系产品基于**Red Hat OpenShift容器平台**构建，这一战略选择带来多重优势：

| 优势维度 | 具体价值 | 业务影响 |
|:---|:---|:---|
| **云原生架构** | 微服务、容器化、DevOps | 快速迭代、持续交付、弹性扩展 |
| **部署灵活性** | 本地、私有云、公有云、混合云 | 适应不同IT战略和合规要求 |
| **高可用保障** | 容器编排、自动故障恢复、负载均衡 | 99.9%+可用性，业务连续性 |
| **资源效率** | 动态资源调度、按需扩展 | 降低基础设施成本20-40% |
| **生态兼容** | 与Red Hat生态深度集成 | 简化运维、统一技能栈 |

#### 6.3.2 统一的AI/ML服务（watsonx集成）

MAS与**IBM watsonx平台**的深度集成，提供企业级AI能力：

| AI服务层级 | 功能组件 | 应用场景 |
|:---|:---|:---|
| **数据科学平台** | Watson Studio | 自定义模型开发、实验管理 |
| **机器学习服务** | Watson Machine Learning | 模型训练、部署、推理、监控 |
| **预置AI能力** | Monitor异常检测、Predict预置模型 | 开箱即用的智能功能 |
| **生成式AI** | watsonx.ai（未来扩展） | 自然语言交互、知识问答、报告生成 |

这种统一AI架构避免了各模块重复建设，确保AI能力的**一致性、可复用性和治理合规性**。

#### 6.3.3 一致的微服务架构与API体系

| 架构要素 | 设计原则 | 实现方式 |
|:---|:---|:---|
| **微服务划分** | 按业务领域解耦 | 资产服务、工单服务、调度服务、分析服务等 |
| **API网关** | 统一入口、安全控制、流量管理 | 认证、限流、缓存、路由 |
| **服务网格** | 可观测性、弹性、安全 | Istio/Linkerd实现服务间通信治理 |
| **事件驱动** | 异步解耦、实时响应 | Kafka事件总线、CQRS模式 |
| **数据一致性** | 最终一致性、 Saga模式 | 分布式事务、补偿机制 |

这种一致的架构设计，使企业能够**灵活组合和扩展功能**，快速响应业务变化，同时降低集成复杂度和运维成本。
